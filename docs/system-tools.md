# System tools

How Highgarden's system tools are put together, and the rules that keep them
safe to run on a real machine.

## Layers

```
src/tools/*.tsx          UI: selection, confirmation, no destructive default
        │
src/mygo.ts              typed client generated by `mygo generate`
        │
internal/app/*.go        services and allowlists (Go)
        │
modules/sysprobe (Rust)  read-only machine and device probing (sysinfo + WMI)
Windows registry/shell   the system's own uninstallers, Run keys and pages
```

The page is trusted by MyGo, so every bound method is callable from it. That
is why the destructive operations take **identifiers**, never paths or
commands from JavaScript:

- `Cleaner.Clean(ids)` looks each id up in the fixed allowlist.
- `Apps.Uninstall(id)` re-lists the registry and runs the command the entry
  itself registered.
- `Startup.SetEnabled(id, enabled)` decodes only ids this app created and
  checks them against the known Run keys and Startup folders.
- `System.OpenPage(name)` accepts names from a map, never a URL.

## Windows-only code

The system services use build tags:

- `*_windows.go`: registry, tokens, `GetSystemTimes`, WMI-adjacent work.
- `*_other.go`: returns `errWindowsOnly` or a safe zero value, so the app
  still builds and the developer tools still work on macOS and Linux.

`modules/sysprobe` compiles everywhere. `sysinfo` provides the cross-platform
snapshot; the WMI device query is behind `#[cfg(windows)]` and returns
`Error::Unsupported` elsewhere.

## Cleaner invariants

The allowlist is built from environment variables on every scan and every
clean, not sent by the page:

| id | path | admin |
| --- | --- | --- |
| `user-temp` | `%TEMP%` | no |
| `windows-temp` | `%SystemRoot%\Temp` | yes |
| `shader-cache` | `%LOCALAPPDATA%\D3DSCache` | no |
| `thumbnails` | `%LOCALAPPDATA%\Microsoft\Windows\Explorer\thumbcache_*.db` | no |
| `crash-dumps` | `%LOCALAPPDATA%\CrashDumps` | no |
| `prefetch` | `%SystemRoot%\Prefetch` | yes |

Guarantees:

1. Every removed path is strictly inside its target folder (`within`).
2. The target folder itself is never removed.
3. Symbolic links are counted as skipped and never followed.
4. Only files are removed; empty subfolders are pruned bottom-up.
5. Locked files fail with an error per file and the rest continue.
6. The confirmation dialog is the only caller of `Clean`; scanning is safe.

## Uninstaller

`Apps` reads these keys and the 32-bit view:

- `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall`
- `HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall`
- `HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall`

`DisplayName` is required; `SystemComponent=1` is skipped. The service keeps a
stable id (scope + key + subkey) and does not keep a cached list between calls,
so `Uninstall` re-resolves the entry and runs its `UninstallString` with
`cmd /c`, in `InstallLocation` when that exists. The uninstaller is the
program's own and may request elevation or open its own window.

## Startup

Registry entries are moved, not deleted:

- Disabling reads the value and its type (`REG_SZ` or `REG_EXPAND_SZ`), writes
  it to `Software\Highgarden\StartupDisabled` in the same hive under a
  base64-encoded `path\0name` value name, then deletes the original value.
- Enabling reverses the move.
- Startup folder entries are renamed with a `.disabled` suffix; the list shows
  them as disabled.

Ids are base64-encoded JSON containing scope, kind, key path and value name.
The encoder is not a security boundary: every enable/disable re-checks the
scope and key against the fixed list of Run keys and computes the folder from
the environment.

## Adding a system tool

1. Add metadata in `src/tools/index.ts` and a component in `src/tools/`.
2. Add read methods to a Go service in `internal/app/`; bind it in `main.go`.
3. Run `bunx mygo generate`.
4. For destructive work, accept ids, build the allowlist in Go, validate the
   target again at action time, and require a confirmation in the UI.
5. For low-level probing, extend `modules/sysprobe` (read-only) rather than
   shelling out to PowerShell.
6. Test the safety checks, not only the happy path:
   `go test ./internal/app`.
